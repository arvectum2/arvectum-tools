## Что поддерживаем

- **iPad:** нативный адаптивный интерфейс на iPadOS в портретной и горизонтальной ориентации; Split View, изменение ширины окна, Stage Manager там, где поддерживается устройством и ОС; клавиатура, Dynamic Type и VoiceOver.
- **iPhone Duo:** складной iPhone на iOS 27, закрытый внешний дисплей **5,4 дюйма**, раскрытый внутренний **7,6 дюйма**; live-переход между состояниями без перезапуска операции, меняющиеся ширина, ориентация и доступные области, многозадачность/Split View на раскрытом дисплее. Официальная презентация: https://www.apple.com/uk/newsroom/2026/09/apple-unveils-iphone-duo/
- **Обычный iPhone:** не ухудшать экран и жесты при адаптации. Размеры окна/геометрия — первичный сигнал для UI; тип устройства сам по себе не означает «планшетный» экран.
- **Без отдельного приложения для Duo:** один продукт и одна кодовая база, разные компоновки на базе существующих SwiftUI/UIKit API и актуального Apple SDK. Не строить критический UX на ещё недоступных специальных Duo API.

## Общие критерии приёмки — Core / совместный QA

- [ ] **D0 · Аудит:** для каждой iOS-утилиты записать текущие supported device families, UI-технологию, ограничения поворота, места фиксированной ширины/высоты, window-scene lifecycle, доступность нужного iPad/Duo simulator/runtime.
- [ ] **D1 · Layout:** компактная/средняя/широкая компоновки, portrait/landscape, text scaling, safe areas, keyboard, popover, sheet, picker, context menus; никаких обрезанных кнопок или обязательной горизонтальной прокрутки.
- [ ] **D2 · Изменение конфигурации:** resize без сброса вводимого текста, поиска, выбранного объекта/заметки, фильтров и навигации; переход Duo закрыт ↔ открыт во время активной операции — без дублей или повреждения данных. Не предполагать фиксированную геометрию и не считать любое сворачивание приложения завершением задачи.
- [ ] **D3 · Специальные устройства:** iPad Split View/Stage Manager и Duo closed/open/Split View проверять на доступных SDK/симуляторах; реальные камеры, Shortcuts, HealthKit, уведомления, импорт из Files и другие системные зависимости проверять на физических устройствах по необходимости. Недоступные симуляторы фиксировать как блокер QA, а не имитировать подтверждение.
- [ ] **D4 · Accessibility:** VoiceOver, Dynamic Type (включая accessibility sizes), контраст/Light-Dark, цели касания, фокус клавиатуры, внешние клавиатуры, управление без длительного удержания там, где жест критичен.
- [ ] **D5 · Безопасность и релиз:** миграция и сохранение всех существующих локальных данных, жизненный цикл задач, тесты памяти на большом экране; правильные ориентации/скриншоты/метаданные App Store. Фактическое включение iPad target family «1,2» и заявление Duo-совместимости — только после подтверждённого app-specific QA и отдельного релизного решения; существующие подписанные/отправленные сборки не менять.
