# Arvectum Tools Core — проверенная базовая точка (18.10.2026)

## Назначение

Эта запись фиксирует **инженерную baseline** для дальнейшей независимой работы над приложениями. Это **не** релиз приложения в App Store и не разрешение интегрировать незавершённые экспериментальные ветки. Опорная метка в Git: `core-baseline-2026-10-18` (ставится на merge-коммит этого изменения); история до интеграции: `7681f55`.

## Состав baseline

- Monorepo: постоянные владельцы `core/`, `chickmark/`, `pushkin/`, `photo-pdf-to-size/`, `what/`, `where/` и `growth/`. Только main является общей интеграционной базой.
- Один SwiftPM продукт `ArvectumCore`: дизайн-токены, stateless JSON codec с Foundation-совместимым wire format и локальные privacy-safe OSLog события.
- Обновления SDK контролируются каталогом `core/dependencies/catalog.json` и проверками SwiftPM lockfiles. Без автоматического включения непроверенных major-обновлений.
- Общие автоматические ворота: architecture, lockfiles, dependency projections, Swift unit, path-scoped CI/consumer builds; Store review и физический QA не выводятся из CI.
- Ветки `feature/core-adaptive-layout-spike-20261016` и отдельные product/release worktrees **не** входят в стабильный Core без самостоятельного merge и QA. Where? не реализован, Growth Agent на паузе.
- Датированный статус релизов — в [PORTFOLIO.md](PORTFOLIO.md), фактические требования и следующие задачи — в [ROADMAP.md](ROADMAP.md).

## Локальный проверочный протокол

**Mac mini, 18.10.2026; Xcode 27.1 (27A9275), Swift 6.4, arm64.** Проверено на чистом worktree от `origin/main`, без вмешательства в пользовательские iOS-приложения.

| Проверка | Результат |
| --- | --- |
| `python3 core/tools/check_architecture.py` | PASS, исходники и структура проходят контракт |
| `python3 core/tools/check_swift_lockfiles.py` | PASS, lockfiles соответствуют Core SDK catalog |
| `python3 core/tools/sync_dependencies.py --check` | PASS, app projections согласованы |
| `swift test --package-path core` | PASS, 6/6 (включая совместимость старого JSON и отказ на повреждённой схеме) |
| Документальный diff | Только Core: продуктовые исходники, пользовательские данные и настройки подписания не менялись |

**Воспроизводимый локальный вход:** `bash core/tools/verify_baseline.sh` из любого каталога. В GitHub проверять архитектурный job и Core CI; всякий переход к новому приложению требует собственной сборки, QA и release approval.

## Правила безопасного продолжения

1. Перед работой `git fetch origin` → ответвление от свежего `origin/main`, отдельный короткоживущий worktree; сохранять чужие dirty worktrees и незамёрженные commits.
2. Общий код — только после доказанного использования минимум двумя продуктами. UX и схемы хранилищ не переносить из отдельных приложений в Core.
3. Любые обновления форматов/SDK — с regression-тестом обратной совместимости, привязанными потребителями и rollback-планом.
4. Не путать App Store submission, `READY_FOR_SALE`, release tag, QA на симуляторе, реальный iPhone/Watch и подтверждённую монетизацию.
5. Следующую опорную точку оформлять новым датированным документом или заменять текущий указатель в [README](README.md); этот отчёт сохранить как snapshot.

## Не включено в baseline

Не интегрированы AdaptiveLayout spike, StoreKit review scheduler и product-specific новые функции. Отдельные ветки сохраняются; отсутствие их в main является сознательной границей стабильности, а не потерей задач.
