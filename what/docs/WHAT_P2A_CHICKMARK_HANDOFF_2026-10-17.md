# Ухват → ChickMark: добровольное разовое напоминание (17 октября 2026)

## Функция

В «Ухвате P2a QA» в действиях сохранённой **текстовой заметки, видеозаметки либо голосовой записи с готовой расшифровкой** появилась кнопка **«В ChickMark»**. Передача начинается только по явному нажатию и подтверждению пользователя. Автоматические напоминания P6b, доставка Watch и редактирование/открытие Inbox не вызывают передачу. Оригинальные аудио и видео **остаются в Ухвате**, ChickMark получает только текст/транскрипцию (если она есть), тип, время, UUID и локальную ссылку на оригинал.

### Протокол передачи и приватность

1. `core/packages/ArvectumInterapp/ReviewNoteHandoff.swift` — общий Foundation-контракт V1 без сетевого провайдера, с UUID исходной заметки, временем, типом (`text/audio/video`), полной UTF‑8 расшифровкой (максимум 32 KiB), случайным nonce и ограничением срока действия **5 минут**.
2. «Ухват» спрашивает разрешение на **временную запись в системный буфер обмена**. Только после нажатия «Продолжить» сохраняет JSON как короткоживущий `UIPasteboard` item (`localOnly`, `expirationDate`) в собственном двоичном типе и стандартном текстовом представлении `uhwhat-review-v1:` + Base64(JSON). Содержимое остаётся расшифровываемым для других приложений, которым пользователь позволит читать буфер, поэтому UI честно предупреждает о временной замене буфера. Не используется сеть, iCloud/CloudKit или App Group.
3. URL **`chickmark-review://review-import/<nonce>`** содержит **только случайный nonce**, не текст или source UUID. Этот новый scheme зарегистрирован отдельно от старого `habits-arvectum`, поэтому опубликованная ранее версия ChickMark не будет *молча* «успешно» обрабатывать неизвестный запрос: отсутствующий получатель сообщает ошибку и предлагает обновить приложение.
4. Получатель сначала показывает экран с системной **SwiftUI `PasteButton`**. Паста происходит только по жесту пользователя с разрешения iOS; прямое `UIPasteboard.general.data(forPasteboardType:)` оказалось ненадёжным на iOS 27 Simulator (nil даже после обычного `Button`), и этот подход был удалён. Получатель заново проверяет nonce, срок, тип, максимальную длину и локальную source URL. Только потом открывает отдельную форму-предпросмотр, где можно прочитать текст, выбрать дату и подтвердить «Создать».
5. `ReviewNoteImportService` создаёт **обычный SwiftData `OneOffReminder`** со стабильным исходным UUID, датой будущего напоминания и кратким названием, **не Habit** и не habit completion. Полный текст/источник/тип/дата хранятся атомарно в отдельном `Application Support/ChickMark/note-review-attachments.json`, доступном через пункт «Читать заметку» в меню разовой задачи. Повторная передача того же UUID не создаёт дубль; удаление одноразовой задачи удаляет её вложение.
6. **Приватность уведомлений**: если у разового напоминания существует импортированное вложение, ChickMark показывает на экране блокировки только общий заголовок «вернуться к заметке» и стандартный текст. Полная транскрипция не попадает в local notification title/body. Ранее созданные обычные разовые напоминания сохраняют привычные названия в своих уведомлениях.
7. В `ChickMarkBackup` добавлено **необязательное** поле `reviewNotes`, не требующее повышения версии JSON-формата или миграции SwiftData привычек. Экспорт/merge/replace защищают отсутствующие вложения и не добавляют note без OneOff. Старые backup без `reviewNotes` продолжают импортироваться.

## Не закрыто / релизные ограничения

- Полное физическое прохождение обеих **подписанных** новых версий на одном iPhone с разрешёнными уведомлениями, системной доставкой push, повторной отправкой после уже созданной задачи и открытием deep link из ChickMark в исходный аудио/текст/видео — **не проводилось**.
- На iPhone Duo Simulator для ChickMark уже был отказ в разрешении на уведомления, поэтому E2E «Создать» подтверждает **безопасный отказ**, тогда как успешная запись SwiftData подтверждена отдельным unit/in-memory тестом. Это не равно полной UI-приёмке создания при разрешённых уведомлениях.
- Объём временного буфера ограничен 32 KiB текста; при превышении показывается ошибка, исходный файл сохраняется. Транскрипции аудио, которых ещё нет на iPhone, не передаются; поздние правки в «Ухвате» **не синхронизируются автоматически** с ChickMark (снимок на момент явного действия). Переход к оригиналу зависит от установленного Ухвата P2a и его URL scheme.
- Импортированные заметки локальны для установки ChickMark; их текст не синхронизируется через CloudKit и не передаётся в SDK аналитики/рекламы. Об этом нужно написать в интерфейсе и release privacy disclosure при выпуске. Протокол через pasteboard требует дополнительного privacy/device QA на настоящем iPhone.
- **Нет релиза, нет обновления физических QA**, основной «Ухват»/ChickMark и опубликованные бинарники не менялись. Работа выполнена в отдельном worktree/branch `feature/what-chickmark-note-handoff-20261017` на ArvectumSSD, не в `main`.
