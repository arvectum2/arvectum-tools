# Ухват · Быстрый QA перед освобождением iPhone и параметрический long-video stress (19.10.2026)

## Что физически проверено

На реальном iPhone 13 был установлен поверх существующего QA приложения отдельный подписанный bundle `ru.arvectum.tools.what.multimodalqa` версии **1.1.0 build 8**. Никакого `uninstall`, сброса хранилища, перехода в production bundle или изменения пользовательской версии не было. Перед установкой прочитан только метаиндекс QA-библиотеки, после установки повторён побайтовый снимок индекса: **полное совпадение, 18 заметок (15 video, 3 text)**. Через `what-physical-qa=verify` на устройстве загружены AVURLAsset двух последних сохранённых MOV — **339.82s и 37.00s**, обе видеодорожки и обе аудиодорожки есть, оба файла playable. Оригиналы остались на телефоне.

Это **reinstall той же версии, не upgrade на новый signed build**. Данные production не читались/не менялись. Экспортированные на Mac JSON-файлы с метаданными QA допустимо удалить после сверки, оригинальные медиа никогда не экспортировались.

## Никакого восьмиминутного лимита

Предыдущий `480s` был выбран произвольно. В QA-only `PhysicalCaptureQAProbe` добавлен `what-physical-qa=long what-physical-qa-seconds=N` с целым N в пределах 60–900; без явного корректного параметра тест не начинает запись. Для воспроизведения старого результата режим `480s` остаётся. После запуска не реже чем раз в 30 секунд `timeline.json` фиксирует elapsed, `isRecording`, `isPreparing`, `isSaving` и message ошибки; внеплановый stop сохраняет точное elapsed, не превращая прерванную сессию в PASS. Уже существующий disk preflight сохраняет нижнюю границу 1 GB; не записывать наполнители для имитации ENOSPC.

`swiftc -parse` и `xcodebuild` QA-only iOS generic target: PASS. Локальная попытка полного симуляторного набора с новой QA-only правкой оборвалась в Xcode на этапе компиляции системных модулей (`BUILD INTERRUPTED`), до тестов; это **не** тестовый PASS. Ранее PR #124 имел **126 пройденных тестов** для кода до новой диагностической правки. Требуется GitHub CI при интеграции.

## Не притворяться, будто завершены аппаратные риски

Нужны отдельно: real foreground 6–10+ минут без interruption, системный звонок во время активной камеры, настоящий дефицит памяти на *выделенном* тестовом телефоне или через безопасные mock'и, аппаратный reboot Watch с сохранённой очередью, реальный радио-offline, длительная запись 30–120 минут, обновление реальной подписанной production версии с сохранением пользовательских данных. Не трогать для QA личные BT/Wi-Fi/pairing и не заполнять хранилище пользователя. Отсутствие оборудования/безопасного канала тестирования обозначать как BLOCKED, а не DONE.
