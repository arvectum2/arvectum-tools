# Ухват — диагностика остановки длительного видео без потери файлов (19.10.2026)

## Почему

При ранее проведённом реальном тесте 480-секундной QA-записи (отдельный iPhone 13 QA bundle) файл MOV перестал расти примерно через **340 с**, хотя поверхностный статус SwiftUI оставался `isRecording=true`. После завершения *только QA процесса* удалось восстановить воспроизводимую 339,82-секундную запись с аудио и видео. **Непрерывная длительная запись не подтверждена.**

## Безопасное диагностическое изменение

Только для `REVIEW_HANDOFF_QA` добавлена `VideoCaptureController.qaRecordingTransport()`, читающая на **той же serial AVCaptureSession queue**:

- `AVCaptureSession.isRunning`;
- `AVCaptureMovieFileOutput.isRecording` (отдельно от SwiftUI `isRecording`);
- текущий номер сегмента и размер существующего MOV-файла (число байт либо -1, если файл отсутствует).

Каждые 30 секунд в QA-only атомарный `What/PhysicalProbe/timeline.json` записывается transport snapshot плюс ранее существовавшие `isRecording/isPreparing/isSaving/error`. Диагностика **не читает содержимое видео, аудио или текст заметок**, не передаёт данные на сервер, не запускает камеру сама, не изменяет `VideoCaptureController` поведение в production. В обычном App Store билде метод исключён компилятором.

## Локальное подтверждение

- `swiftc -frontend -parse` обоих изменённых Swift-файлов — PASS.
- Изолированный `WhatMultimodalPhysicalQA` XcodeGen target, `REVIEW_HANDOFF_QA` и Xcode 27.1, `generic/platform=iOS Simulator`, `xcodebuild build` — **BUILD SUCCEEDED**. Логи: `/Volumes/ArvectumSSD/Arvectum/tmp/what-qa-liveness-20261019`.
- GitHub CI для отдельной PR-ветки проверяется отдельно. Предыдущий полный WhatIOSTests: 126 tests / 0 failures / 3 skips (до этого диагностического изменения).

## Что не подтверждено

- Непрерывная 8+-минутная реальная запись и причина физического обрыва ~340 секунд.
- Когда `writerRecording=false` при `isRecording=true`, диагностика только фиксирует расхождение; автоматическое сохранение/откат без корректного callback не добавляется.
- Никакого физического стресс-теста, искусственного ENOSPC, системного звонка или сброса пользовательских данных здесь не запускалось.

Следующий обоснованный физический прогон — на изолированном QA приложении, после проверки батареи, свободного места, разрешений и гарантии сохранения исходных файлов. Сначала анализ `timeline.json`, только затем изменения production recovery logic.
