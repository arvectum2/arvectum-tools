# Ухват · Crash-safe удаление локального видео · 19.10.2026

## Проблема

Раньше приложение записывало индекс без удалённой видеозаметки до удаления `Videos/{UUID}.mov`. При краше или ошибке хранилища файл оставался на диске, уже не отображаясь в Inbox, а доказательство намерения удалить было потеряно.

## Исправление

`LocalNoteRepository` хранит атомарный `pending-local-video-deletions.json`, содержащий только UUID явно удаляемых видео. Порядок: записать намерение -> сохранить индекс без заметки -> удалить только канонический `Videos/{UUID}.mov` -> удалить UUID из журнала. После ошибки журнал остаётся, следующий запуск повторяет финализацию. При ошибке начальной записи намерения индекс и исходный MOV остаются нетронутыми.

Индекс никогда не смешивается с Watch `recordings.json`. Новая попытка сохранения с UUID ожидающего удаления блокируется, а Inbox скрывает логически удалённые записи. `PhoneStore` перечитывает Inbox после отказа файловой очистки и отменяет напоминания для уже удалённых UUID. Непонятные MOV, camera journals, незавершённые сегменты и исходники импорта не обрабатываются массовой очисткой.

## Автотесты

1. Отказ FileManager при удалении MOV: intent остаётся, после relaunch очистка завершена, исходник импорта цел.
2. Отказ атомарной записи intent: индекс и оригинал остаются без изменений.
3. Crash после записи intent, но до обновления индекса: relaunch завершает обе стадии.
4. Неизвестный MOV в Videos не трогается.

Целевые `LocalNoteRepositoryTests`: 8/8. Полный `WhatIOSTests`: 124 выполнено, 3 ожидаемых пропуска, ноль ошибок. Xcode 27.1 / iOS 27 Simulator. Исходные данные реальных устройств и App Store не тронуты.

## Открытые границы

Проверка на физическом iPhone с реальным ENOSPC и обновлением подписанной версии ещё не выполнена. Неизвестные старые MOV нельзя объявлять ненужными на основании отсутствия в индексе: они могут быть источниками восстановления.
